Research Framing

Questions Guiding the Project

The first update turns the project from a broad cyber deception idea into a focused research problem: how can a layered honeynet make attacker decision-making observable?

Navigation

How does layered deception influence attacker navigation?

This question focuses on whether attackers follow the paths created by deceptive services, credentials, hosts, files, and cloud references.

Decisions

Which deception artifacts affect attacker choices?

The design treats credentials, honeyfiles, fake accounts, and cloud tokens as probes that reveal attacker priorities and assumptions.

Depth

Can staged layers increase meaningful engagement?

The project evaluates whether progressive exposure encourages attackers to move beyond initial access into host and data-oriented behaviour.

Working Hypothesis

Layered deception should reveal richer attacker behaviour than isolated honeypots.

Path Influence

Attackers interact with decoy-induced paths that would not exist in a flat sensor.

Decision Evidence

Artifact use shows what the attacker believed to be valuable or reachable.

Lifecycle Coverage

Observation expands from initial contact to internal movement and data targeting.

Literature Review

What the Literature Establishes

The review frames the project as a response to a visibility problem: conventional honeypots are useful sensors, but they rarely sustain the environmental continuity needed to observe multi-stage attacker behaviour.

Problem

Single-Layer Blindness

Traditional low- and high-interaction honeypots are strong at capturing reconnaissance, brute-force attempts, and initial exploitation, but they are structurally weak at observing lateral movement, credential harvesting, collection, and exfiltration.

Need

Environmental Continuity

Multi-stage observation requires plausible continuation paths. Attackers need to encounter a believable progression from exposed services to internal hosts and then to higher-value data or cloud resources.

Lens

Behavioural Evaluation

The literature motivates moving beyond detection-only metrics toward behavioural measures such as misdirection, delay, engagement depth, path expansion, and tactic-level observation.

Research Themes Reviewed

Honeypot and honeynet taxonomy
Adaptive cyber deception
Military deception principles
Host and Active Directory deception
Honeytokens and decoy data
MITRE ATT&CK / D3FEND mapping

Core Literature Gap

Existing work discusses deception techniques, adaptive honeynets, and defensive frameworks, but there is still limited controlled evaluation of how layered deception changes attacker navigation across network, host, and data/cloud stages.

Project response

Design an integrated deception environment that makes attacker paths observable, comparable, and measurable.

Evidence Matrix

How the Reviewed Work Shapes the Design

This matrix links literature themes to concrete design decisions so the page reads like a project rationale, not just a list of sources.

Literature Area Key Finding Design Implication
Traditional Honeypots They capture scanning, brute force, and initial exploitation well, but often stop before post-compromise behaviour becomes visible. The architecture needs more than an exposed service layer; it needs believable follow-on systems.
Adaptive Deception Deception is more convincing when the environment responds to observed attacker actions rather than exposing everything at once. Staged activation is used to reveal deeper assets only after meaningful attacker interaction.
Host / AD Deception Internal identity systems and credentials are central to modern lateral movement decisions. The host layer includes Active Directory, decoy accounts, credential placement, and enterprise-style hosts.
Honeytokens and Data Lures Tokens and decoy files work best when they are uniquely attributable and connected to plausible attacker goals. Cloud keys, honeyfiles, and decoy storage are tagged so their use can reconstruct attacker intent.
MITRE ATT&CK / D3FEND Standard frameworks provide a vocabulary for connecting observed actions to tactics and defensive deception techniques. Telemetry is mapped to tactics such as discovery, credential access, lateral movement, collection, and exfiltration.

Argumentative Synthesis

Design Logic Derived From the Review

Continuity Before Complexity

The architecture does not simply add more decoys. It links decoys into a plausible enterprise path so that each attacker action can reveal intent, capability, and decision-making.

Metrics Must Match Deception Goals

Detection rate alone cannot show whether deception changed behaviour. The project therefore emphasizes misdirection, delay, and engagement depth as behavioural outcomes.

Attacker Skepticism Matters

Literature on attacker decision-making suggests that deception fidelity and perceived value shape whether attackers continue, disengage, or change tactics.

Artifacts Need Identity

Decoy credentials, honeyfiles, services, and cloud tokens must be uniquely tagged so interactions can be reconstructed into cross-layer paths.

Design Requirements

What the Architecture Must Support

The literature review produces practical requirements for the system. These requirements are used to evaluate whether the design can support meaningful attacker observation.

1

Plausible Entry Points

The network-facing layer must look worth probing without appearing unrealistically vulnerable or empty. Service banners, exposed ports, and initial credentials should support believable reconnaissance.

2

Internal Continuation Paths

The attacker must discover internal hosts, identities, shares, and credentials that make lateral movement plausible enough to continue the session.

3

High-Value End Targets

The data/cloud layer must provide realistic objectives such as fake storage, API keys, documents, and cloud references that reveal collection and exfiltration intent.

4

Cross-Layer Observability

Logs cannot remain isolated per service. The system must preserve identities, timestamps, and artifact IDs so attacker sessions can be reconstructed across layers.

Design Principle

Progressive Revelation

The system should not reveal every asset at once. Instead, each layer should become more visible as the attacker demonstrates interest, capability, or commitment.

Design Tradeoff

Fidelity vs. Safety

The architecture must be realistic enough to sustain interaction while staying isolated, controlled, resettable, and free of genuine sensitive data.

Analysis Need

Behaviour Before Alerts

The goal is not only to detect an intrusion. The goal is to observe what attackers do next, what they value, and how deception changes their path.

Architecture Design

Layered Honeynet Model

The proposed system is organized into three deception layers. Each layer corresponds to a different stage of attacker activity and produces telemetry for behavioural reconstruction.

Reconnaissance and Initial Access

Network Deception

Attacker-facing services create the first believable contact point and capture scanning, probing, banner interpretation, exploit selection, and credential attempts.

Components

T-Pot CE, SSH/HTTP/SMB exposure, crafted banners, simulated subnets.

ATT&CK Mapping

Reconnaissance, initial access, discovery, credential access.

Telemetry

Service logs, connection metadata, brute-force attempts, command traces.

Execution and Lateral Movement

Host / Active Directory Deception

The internal enterprise layer gives attackers a believable environment for enumeration, credential harvesting, privilege path discovery, and lateral movement.

Components

GOAD Active Directory, domain controller, workstation, file server.

Deception Artifacts

Decoy accounts, fake admin paths, planted credentials, honeyfiles.

Observation Target

Enumeration, privilege escalation attempts, credential reuse, host traversal.

Collection and Exfiltration

Data / Cloud Deception

Higher-value lures test whether attackers pursue cloud targets, inspect decoy data, reuse harvested credentials, or attempt exfiltration-like actions.

Components

HoneyLambda, decoy S3 buckets, fake API keys, cloud references.

Deception Value

Plausible data targets create a reason for attackers to continue beyond host access.

Observation Target

API calls, token usage, storage enumeration, collection behaviour.

Telemetry and Measurement

How Behaviour Becomes Evidence

The architecture is designed not only to attract interaction, but to preserve the sequence and meaning of that interaction across layers.

Artifact Tagging

Each decoy service, credential, file, account, and cloud key receives a unique identity so later interactions can be traced back to the lure that caused them.

Path Reconstruction

Events are correlated into attacker sessions, showing how actions move from network access to host exploration and data/cloud targeting.

Behavioural Metrics

Misdirection, delay, and engagement depth translate raw telemetry into evidence about whether deception influenced attacker behaviour.

Normalized Event Fields

A consistent schema makes heterogeneous logs comparable across network services, Windows hosts, Active Directory, and cloud simulation components.

Timestamp

Metric Operationalization

Misdirection

Measured through decoy-path interactions, fake credential use, honeyfile access, and movement toward designed lure routes.

Delay

Measured through time spent interacting with deceptive assets, repeated reconnaissance, and detours caused by planted artifacts.

Engagement Depth

Measured by layer progression, diversity of actions, number of artifact categories touched, and tactic coverage.

Experimental Scope

Controlled Testbed Design

The project uses a contained virtual environment so the architecture can be evaluated safely, reset cleanly, and reproduced for repeated observation.

Proposed Lab Roles

LOG01 - Central Monitoring

Receives logs from all deception layers and supports normalization, correlation, and later analysis.

TPOT01 - Network Honeypot Layer

Hosts exposed deception services and captures first-stage attacker interactions.

DC01 / WS01 / FS01 - Internal Enterprise Layer

Represents Active Directory, workstation activity, and file resources for post-compromise observation.

Safety

Containment Principles

The environment is isolated from production systems, uses only fabricated data, and restricts outbound behaviour through controlled network boundaries.

Reproducibility

Resettable Experiments

Snapshots and documented configuration states allow experiments to be repeated without carrying over attacker modifications or contaminated artifacts.

Scenarios

Comparative Observation

The design can support comparison between limited exposure, full layered exposure, and staged activation to understand how architecture changes behaviour.

Contribution Positioning

What This Update Establishes

The literature review identifies the lack of controlled, integrated evaluation for layered deception across multi-stage attacker behaviour.

The proposed three-layer design directly responds to the need for environmental continuity and post-compromise observation.

The project shifts evaluation from alert generation toward behavioural evidence: how attackers navigate, what lures they follow, and how deeply they engage.
